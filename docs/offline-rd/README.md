# MaxCompute＋Dataphin 离线数据资产研发

面向以 SQL 为主的中间层、应用层研发。目标不是让 Agent 直接替人发布，而是把需求、资产、模型、SQL、验证、发布和优化串成**可审查、可回放、可回退**的内网流程。

## 推荐实施顺序

1. **第 0 阶段：只读辅助。** 先固化模板、元数据快照和 20–50 个历史需求金集；Agent 只生成候选和证据包。
2. **第 1 阶段：影子评审。** 与人工方案并行，对资产召回、粒度/口径错误、SQL 校验和审查耗时做盲测。
3. **第 2 阶段：受控生成。** 允许在开发环境创建草稿；预编译、样例运行、结果校验通过后仍由人提交。
4. **第 3 阶段：审批式自动化。** 仅对低风险、可回退任务开放提交/发布工具；高影响变更保持双人审批。

任何阶段都不能把企业 SQL、元数据、日志或模型上下文上传到此 GitHub 库。这里的模板只提供结构和非敏感示例。

## 最小落地目标

选一个中等复杂度、近三个月重复出现过的应用层需求，以四周为一期：首周记录人工基线，第二周只读助手，第三周影子评审，第四周小范围受控生成。成功条件同时包括正确性不下降、P50/P90 交付时长改善、人工修改量下降、资产复用提高，且新增维护成本可接受。
