# 实践包二：应用层需求到交付

## 输入输出

输入：批准的业务口径、消费对象、交付频率/SLA、历史范围、安全等级。输出：可审查的输入契约、资产选择记录、指标计算、应用 SQL、分区/调度依赖、结果核对、发布及回补方案。

## SOP

1. 把自然语言需求转成指标卡：业务含义、分子/分母、过滤、时间窗、维度、单位、空值、去重、有效期和 owner。
2. 选择中间层资产，记录候选、排除原因、版本和血缘；若直接读 ODS，必须说明公共层缺口及治理计划。
3. 为每个输出字段维护“来源字段 → 转换 → 口径版本 → 校验”映射，指标表达式与展示格式分离。
4. 设计分区和调度：业务日期与运行日期区分，声明上游分区、完成条件、跨天偏移、重跑范围和 SLA。
5. 生成 SQL 后依次做预编译、EXPLAIN、固定小范围运行、结构校验、业务对账和边界样例；每一步保留证据。
6. 检查幂等：同一分区重复执行结果一致；覆盖、追加、合并策略明确；中途失败不留下可见半成品。
7. 处理迟到与回补：定义迟到窗口、受影响分区、下游传播、资源预算、暂停条件和回退。
8. 发布前比较开发/生产对象版本、权限、依赖和发布清单；发布后读取生产终态及首个产出分区，不以“请求已提交”结束。

## 发布门禁

- Dataphin Basic 与 Dev-Prod 模式行为不同：Dev-Prod 提交后仍需发布，Basic 提交可直接进入生产；必须由企业版本核验决定状态机。
- 发布通常只包含勾选对象；未发布的上游变更可能导致下游使用旧逻辑，因此发布清单要对比依赖版本而非只看任务成功。
- 需要回补、重跑或提交/发布的动作进入 W2 权限，必须有影响分区、资源预算、审批人、停止条件和回退。

官方依据：[Dataphin SQL 代码任务](https://help.aliyun.com/zh/dataphin/semimanaged-v4/user-guide/computing-tasks/)、[发布管理](https://help.aliyun.com/zh/dataphin/semimanaged-v4/user-guide/release-management-standalone-deployment)。实际部署版本、研发模式和审批流程仍须内网核验。

## 典型边界用例

月末/跨年、空分区、重复事件、迟到更正、维度历史版本、零分母、时区、主键为空、枚举新增、源字段变更、回补覆盖在线分区。每个用例应有输入快照、预期结果和失败解释。

## 价值验收

按阶段比较需求澄清次数、资产选取时间、SQL 人工修改量、首次评审通过率、发布后缺陷、回补次数和端到端 P50/P90；生产收益必须来自真实试点，不能由合成 SQLite 案例外推。
