# 实践包三：存量任务与链路优化

## 原则

先诊断、后建议、再审批执行。固定数据范围、代码版本、配额、优先级、缓存和并发条件；优化收益必须同时满足结果一致、资源/时延改善和下游无回归。

## SOP

1. **建基线**：任务与 SQL digest、输入分区/数据量、队列/Quota、提交/开始/结束时间、扫描/CPU/内存、重试、输出 hash/统计量。
2. **分离等待与计算**：提交至首次获资源属于等待，真正运行属于计算；先处理主要矛盾，避免改 SQL 掩盖配额问题。
3. **读计划和诊断**：用 EXPLAIN 看 job/task/operator、依赖、扫描和数据交换；计划输出超过接口上限时分段保存并注明截断，不能假装完整。
4. **定位链路关键路径**：结合实例血缘、上游完成和历史同签名任务，区分单任务慢与长尾/串行依赖。
5. **形成候选**：分区裁剪、消除重复扫描/计算、连接前过滤/聚合、处理倾斜、小表策略、文件布局、依赖并行或配额调整；每项写前提、风险和预计作用机制。
6. **隔离验证**：同一快照 A/B，先做 schema、行数、主键、空值、分布、关键指标和抽样差异，再测多次运行的 P50/P90 与计算消耗。
7. **影响与回退**：下游清单、回补范围、双跑/切换方案、阈值、观察窗、回退 SQL 和 owner。
8. **审批执行并复盘**：只实施获批项；从生产终态读取实测，未达标就回退并记录假设为何不成立。

## 证据解释

MaxCompute EXPLAIN 是编译/计划证据，不是实际运行收益；[Job Insights](https://help.aliyun.com/zh/maxcompute/user-guide/job-insights) 可辅助查看等待、运行、消耗、配额和相似历史，但总体状态不等于每个 worker 状态。包年包月与按量的消耗含义不同，计算量下降也不必然等于同额现金节省。参考：[EXPLAIN](https://help.aliyun.com/zh/maxcompute/explain-1)、[SQL 作业智能诊断](https://help.aliyun.com/zh/maxcompute/user-guide/job-intelligence-diagnosis/)。

## 结果一致性门禁

对整表 hash 不现实或语义不稳定时，采用分区行数、主键集合、列统计、分桶 hash、关键聚合和差异样本组合。浮点、无序聚合、近似函数、非确定函数要定义容差；业务口径一致性独立于 SQL 结果一致性验收。

## 价值

报告等待时长、运行时长、P50/P90、扫描/CPU/内存、失败/重试、关键路径缩短和运维成本；必须注明观察窗口、对照条件和置信限制，禁止只选最快一次。
