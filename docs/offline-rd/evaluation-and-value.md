# 评测、门禁与价值测量

## 三层评测

1. **确定性检查**：JSON/schema、权限策略、SQL 解析/预编译、只读限制、主键/粒度/分区、固定快照结果、预算、轨迹完整性和终态。
2. **模型任务评测**：资产 Recall@K、引用准确率、口径选择、澄清率、SQL 可执行率、工具成功率、越权率和无依据断言率。
3. **人工业务评审**：模型设计、业务关系、口径正确、变更风险、可维护性和建议可操作性；评审人、版本和分歧必须保留。

## 金集设计

从已完成且可脱敏的内部历史任务抽样，数据仍留在企业环境。至少覆盖：新建中间层、复用判断、应用指标、慢 SQL、长链路、口径冲突、信息不足、权限拒绝、迟到/回补、关联放大。每例固定需求版本、元数据快照、批准答案/可接受集合、禁止动作和证据。

公开仓库现有 40 例 SQLite 合成回归只验证 Harness 机制；不能作为 MaxCompute、Dataphin 或企业模型效果证明。

## 上线门槛示例

- 越权写入、无审批发布、泄露敏感上下文：0 容忍。
- 正确引用必须指向当前快照，截断/缺失必须披露。
- SQL 结果一致性通过后仍需业务口径评审；二者不得合并成一个“正确率”。
- 信息不足时应澄清或拒绝，不能为了完成率猜口径。
- W2 动作需 100% 影响分析、审批、幂等键、回退和终态证据。

阈值要用历史人工基线和风险偏好校准，不能直接照搬公开 benchmark。

## 价值账本

对每个试点按阶段记录：人工分钟、等待分钟、模型/计算成本、修改行数、评审轮次、返工、缺陷、复用资产数和发布后运维。建议同时报告：

- `净节省 = 人工时间节省价值 + 可核验计算成本节省 - 模型/平台/维护/评审新增成本`
- `交付改善 = 基线 P50/P90 - 试点 P50/P90`
- `复用率 = 使用既有批准资产的交付数 / 可复用交付数`
- `一次通过率 = 首轮评审无重大问题数 / 总评审数`

四周试点不足以证明长期收益，应注明样本量、需求复杂度、观察窗和学习效应。只有内网真实试点能报告实际收益。
