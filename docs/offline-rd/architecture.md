# 内网数据研发 Agent 参考架构

```text
需求/变更单
   ↓  口径契约与风险分级
上下文装配器 ──→ 版本化证据包（目录/字段/血缘/口径/样例/权限）
   ↓
规划器/模型（企业内网批准服务）
   ↓
策略执行器 ──→ 只读检索 → SQL 预编译/EXPLAIN → 开发运行 → 比对验证
   ↓                 │              │                 │
审批门 ──────────────┴──────────────┴─────────────────┘
   ↓
Dataphin 提交/发布（模式感知） → MaxCompute 生产执行
   ↓
日志、成本、质量、血缘、人工反馈 → 评测集与知识版本
```

## 六个关键部件

1. **需求契约**：业务过程、粒度、时间口径、过滤范围、维度、指标定义、容错、交付 SLA、数据敏感级别；缺一项先澄清，不生成 SQL。
2. **语义与本体层**：把业务概念、指标口径、资产字段和计算逻辑分开建模，以批准状态和版本连接。外键只证明可连接，不能证明业务关系；复合身份必须完整。
3. **上下文装配器**：按任务最小化检索，不把全量元数据塞给模型。上下文包需含 `snapshot_id`、来源、时间、权限主体、对象版本、截断说明。
4. **受控工具层**：工具按读取、推演、开发写入、提交、发布分级；默认只读，参数有 schema、行数/时间/扫描预算，结果必须带终态和证据链接。
5. **Harness**：负责状态机、预算、重试、幂等键、审批、错误分类、轨迹回放和终态核验。模型只提议动作，不拥有隐式权限。
6. **评测与反馈**：确定性门禁检查粒度、主键、分区、依赖、SQL 结果与资源；业务口径、本体关系和可读性由有角色的人工评审。

## 语义边界

| 层 | 回答的问题 | 不负责 |
|---|---|---|
| 业务本体 | 客户、订单、权益等对象是什么，身份和关系如何批准 | 具体表字段和 SQL |
| 指标/口径模型 | “活跃”“收入”等如何定义、何时生效、谁批准 | 物理执行优化 |
| 资产语义 | 哪张表/字段承载概念，粒度、主键、质量和血缘如何 | 自动证明业务关系正确 |
| 计算语义 | 指标怎样由过滤、聚合、关联和时间窗口计算 | 业务审批 |
| OSI/Ossie 映射 | 在规范对象间交换类型、映射和引用 | 替代 Dataphin 或 MaxCompute 执行引擎 |

映射对象至少记录：源对象版本、目标概念版本、映射表达式、复合身份、证据、置信度、状态、审批人、有效期和验证结果。候选关系在批准前不能进入生产问答或自动 SQL。

## 工具权限矩阵

| 等级 | 示例 | 默认策略 |
|---|---|---|
| R0 | 搜索目录、读字段/口径/血缘、读实例日志 | 允许；脱敏、最小字段、审计 |
| R1 | EXPLAIN、预编译、估算、合成数据验证 | 允许；预算与超时 |
| W1 | 开发环境保存草稿、创建临时验证对象 | 任务级授权；幂等、可清理 |
| W2 | 提交、发布、补数据、重跑 | 明确审批；影响分析和回退必填 |
| W3 | 权限变更、删除生产对象、大范围回补 | 默认不开放给 Agent |

每次调用记录 `run_id/task_id/tool/input_digest/context_snapshot/actor/policy/started_at/ended_at/status/evidence/error/budget_after`。重试只能针对超时或可恢复错误；业务校验失败不得自动换参数“试到通过”。
