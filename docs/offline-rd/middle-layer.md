# 实践包一：中间层资产研发与复用

## 问题与前提

输入是批准的需求契约和可访问的元数据快照；输出是可评审的模型方案与 SQL 草案。目标是复用经过验证的公共事实/维度，避免重复建设、粒度混用和关联放大。Agent 不能因字段同名就断言语义相同。

## SOP

1. **抽取业务过程**：事件是什么、发生时间/入库时间各是什么、可重复吗、修正如何表达。
2. **声明粒度**：用一句“每行代表……”描述；列出完整主键、分区键和有效时间。无法给出唯一身份即停止。
3. **拆分事实和维度**：度量的可加性、退化维度、SCD 类型、迟到事实/维度、删除和更正规则。
4. **检索资产候选**：按业务过程、概念、粒度、字段、血缘和质量多路召回；保留未命中原因，不只取名字最像的表。
5. **复用判定**：比较粒度、时间、主键、过滤、数据范围、更新时效、质量、权限和负责人；一项不兼容即降级为“需转换/不可复用”。
6. **设计关联**：声明左右粒度、连接基数和业务谓词；在固定分区上验证连接前后行数、主键重复率、未匹配率和度量守恒。
7. **生成草案**：显式字段、分区裁剪、公共表达式、空值/异常处理；不默认 `select *`，不把预编译成功当业务正确。
8. **质量与影响**：主键唯一、非空、枚举、范围、时效、对账、血缘、下游影响、负责人和处置 SLA。
9. **评审与版本化**：保存需求版本、资产快照、决策记录、SQL digest、验证结果；审批后才成为批准资产知识。

## 关联放大门禁

设连接前左表行数 `L`，连接后行数 `J`，左主键去重数 `K`。至少检查 `J/L`、连接后同一左主键最大匹配数、度量前后总和以及未匹配样本。允许一对多时也必须给出预期上界和后续聚合规则；“存在外键”不是通过条件。

## 失败与恢复

- 口径缺失：生成澄清问题，不猜默认定义。
- 资产元数据过期：重新固定快照并让旧方案失效。
- 候选冲突：并列展示差异和 owner，不让模型自行审批。
- 样例运行通过但业务对账失败：保留失败证据，回到粒度/过滤/时间定义，不自动发布。
- 新建不可避免：记录“为何不可复用”、预计复用者和退役条件。

## 验收和价值

正确性门禁包括完整主键、粒度、分区边界、幂等、迟到/回补、关联基数、对账及下游影响。价值基线记录需求分析、找表、设计、SQL、验证、评审各阶段耗时；试点比较复用率、人工修改行数、缺陷返工率和计算增量，不能只报“生成更快”。
