# 评测体系：确定性回归、模型能力与业务验收

## 评测对象与事实边界

本库的 40 条是结构化动作的工具契约评测，每类 10 条；没有运行 LLM、云平台或公众号分类模型。通过率只表示固定合成快照上的工具行为符合预期，不是自然语言任务成功率、生产可用率或防注入效果。

[Agent 评测工程文章](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)强调需要观察真实最终结果及轨迹，并对随机行为开展多次 trial。本项目据此建议分三层验收。

| 层 | 输入与真值 | 自动检查 | 人工检查 |
|---|---|---|---|
| 工具契约 | 固定动作与快照 | SQL 结果、拒绝写入、预算、映射与回放 | 接口是否符合用途 |
| 模型与 Harness | 未见过的业务问句、批准口径、允许工具 | 检索、执行结果、预算与引用 | 澄清是否适当、解释是否忠实 |
| 业务试点 | 真实用户任务、授权身份、业务结果 | 成功率、延迟、费用、失败分类 | 口径与决策价值、是否需要接管 |

## 四类任务怎么判分

- **数据研发**：生成/修改作业先编译，再检查依赖、增量边界、幂等、数据质量、结果差异和回滚。会生成 SQL 不等于能正确发布作业。本例只覆盖结构检查查询与禁止写入。
- **资产检索答疑**：以人工标注相关资产集合计算 recall@k、MRR；答复引用必须真实且支持陈述。权限过滤前后分别检查，不将不可见资产的存在泄漏给用户。本例为同义词精确匹配基线，不做向量排名。
- **数据分析**：优先比较同快照执行结果；明确行顺序、重复行、NULL、Decimal 容差、时区、币种、汇总粒度和空集合。SQL 文本相同不是必要条件，偶然同结果也不足以证明通用等价。
- **数据 Agent**：任务完成率、正确工具序列、澄清率、越权率、调用预算、恢复行为和证据完整性。本例只检查复合身份和关系工具，以及白名单和预算。

## OSI 与本体专项矩阵

1. 结构：固定 schema、文档引用、字段和概念引用、完整身份。
2. 语义：逻辑字段到物理列、基数、单位、币种、时间字段、过滤条件。
3. 对象：候选实体对齐 precision/recall、重复与遗漏、跨租户冲突。
4. 事实：关系 precision/recall、证据是否支持业务命题、反例是否被排除。
5. 互操作：同一模型在目标引擎上的正确结果与可接受性能；分别报告转换失败与结果不一致。
6. 生命周期：旧版本回放、破坏性变更、审批失效、下游影响及回滚。

## 防止评测泄漏

金标必须由业务负责人审核，按业务域/模板族/时间切分开发和保留集，不能仅随机拆同一问句的改写。固定模型、工具版本、快照与检索上下文。[Snowflake 的评测文档](https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-analyst-evaluations)明确将被评测的验证查询从运行上下文移除，并比较执行结果、回归与延迟；这个做法值得迁移。

本库 40 条既参与开发又参与回归，属于开发集，绝不能对外宣称泛化。接入模型后，建议每条运行至少 3 个独立 trial，保存随机性配置、输入、检索证据、动作、输出和总成本，报告均值、区间与最差类别，不挑最好一次。轨迹只保存工具与任务证据，不要求记录隐藏思维链。

## 模型评审与人工评审

确定性检查先判硬错误；LLM judge 仅评价解释忠实度、可读性和澄清合理性，使用明文 rubric 并保存理由。用人工双盲样本校准 judge，分歧进入仲裁；不能让被评模型自评替代真值。引用正确率按主张逐条看来源能否支持，而不是只看有没有 URL。

## 建议试点门槛（本项目建议，非行业标准）

受限业务域的保留集：关键权限违规 0，批准指标确定性回归 100%，结果正确率 ≥95%，引用支持率 ≥95%；不确定问题必须澄清。延迟和费用由业务 SLA 设定并逐次记录。门槛未达只开放建议模式，发布/回写保持人工审批。上线后按错误类型回流 bad case，经人工确认加入新版本评测集；所有模型、索引、口径变更都重跑。

[Spider 2.0](https://spider2-sql.github.io/)可用于补充企业 SQL 工作流任务，但要注明具体 setting、数据版本和 oracle 条件。排行榜不能替代自家业务集，不把早期论文分数或不同任务设定混作当前模型水平。
